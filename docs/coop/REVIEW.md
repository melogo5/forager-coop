## Осталось — по важности

### Влияет на игру уже сейчас

1. **Втроём-вчетвером постройки и подборы одного гостя не доходят до других гостей** (`sync.cpp` `ApplyGuestSpawn`/
   `ApplyGuestDestroyed`; типы 10–19 не в `kSharedTypes`). Хост применяет их молча и никому не пересылает. Подобранный
   гостем A дроп остаётся у гостя B — его можно подобрать второй раз (дюп). Постройка A появляется у B только если её
   найдёт сверка. Нужна проверка `four.ps1` и пересылка от хоста как обычного spawn/destroy.
2. **Игровой поток хоста может встать на отправке** (`net.cpp`): снимок мира гостю держит `sendLock` этого гостя,
   а `net::Send` из игрового потока ждёт его. Медленный или зависший гость = фриз хоста. Нужна очередь отправки на
   соединение (поток-писатель) или `try_lock` для состояния игрока.
3. **Сессию нельзя отменить, пока не вошёл в мир** (`session.cpp`, `menu.cpp`): опечатка в IP — гость переподключается
   вечно, «Already in a session — restart the game». То же, если хост нажал CREATE и вернулся. Нужна кнопка Back/Esc
   → `session::Leave()`.
4. **Хранилище: любое пришедшее содержимое снимает блокировку** (`storage.cpp:289`), не проверяя владельца — путь к
   двойному открытию и дюпу втроём. Плюс блокировка может застрять (`g_ownOpen`, если меню не открылось; сундук
   уничтожен с открытым меню).
5. **Музей: синхронизация всего списка «кто последний»** (`progress.cpp`): два пожертвования за ~1 с — одно пропадёт,
   а предмет уже снят. Слать дельту.
6. **Ловушки: два игрока, собравшие одну ловушку за время пинга, оба получают улов** (`traps.cpp`). Решать на хосте.
7. **Мобы: уничтожение реплики врага у гостя может прийти хосту как `kGuestDestroyed`** (`sync.cpp` DestroyHook) —
   враг у хоста исчезает без дропа и опыта. Не проверено; дешёвая защита — не сообщать `parEnemy`/`parCritter`.
8. **Первопричина порченых сейвов** — уже в TODO (QUESTIONS.md); `savefix` теперь хотя бы пишет безопасно.

### Надёжность и производительность

9. Сверка мира `O(хост × гость)` и перебор id от 100000 до разрыва в 20000 (`reconcile.cpp`) — рывки на больших
   мирах, возможен неполный список. Хэш по `(object, x/8, y/8)`, обход через `instance_find`.
10. `HerbProcessHook` (`world.cpp`) каждый кадр копирует весь список посадок через встроенные функции; `ForgetInstance`
    (`mobs.cpp`) на каждое уничтожение. `FindBuiltin` создаёт `std::string` на каждый вызов — кэшировать индексы.
11. Отложенные действия (`g_afterWake`) держат сырой `localPlayer` и не ограничены по размеру.
12. Снимок мира шлётся из detached-потока через фиксированные 120 шагов после асинхронного `SaveGame`; персонаж
    гостя — так же. Ждать стабильного размера файла.
13. `Stop()` держит `g_lock` во время Steam-отправок; Steam-поток может не перезапуститься при быстром Leave→Host;
    соединение может зарегистрироваться после `Stop()`; `g_servers` LAN и `g_accepted` Steam не ограничены.
14. Неограниченные контейнеры до конца сессии: `g_destroyedOnHost`, `g_hostOwnedDrops`, `g_guestDrops`, пары
    реплик после `CollectNow`.
15. Утечка `ds_list` инструмента марионетки при каждом выходе/входе (`puppet.cpp` `ShowTool`), если `CleanUp`
    игрока его не уничтожает — проверить.
16. Имена гостей `CON`/`NUL`/`COM1` проходят `SafeName`; `Bob` и `bob` делят один файл (NTFS без регистра).

### Доверие к сети (важно, только если играть не с друзьями)

Рукопожатия нет, порт слушает все интерфейсы, проверка протокола только предупреждает. Хост принимает от гостя без
проверки: индекс объекта для создания, id цели удара/уничтожения (вплоть до игрока хоста), hp, опыт (NaN), монеты
и время (сообщения хоста — от гостя), сверку, землю/биом, состояние станков, эффекты навыков с произвольным `argc`.
Для игры с друзьями по LAN/VPN это терпимо; перед публичным релизом — hello с версией и токеном, проверка роли
отправителя на каждый тип сообщения, `std::isfinite` и диапазоны. Отладочный порт (`COOP_DEBUG_PORT`) слушает только
127.0.0.1, но без токена умеет вызвать любой адрес — вынести из релизной сборки.
