# Forager Coop — архитектура v1

Как реализуем [SPEC.md](SPEC.md) поверх игры.
Всё, что помечено «проверено», наблюдалось в игре трассировщиком (`native/src/trace.cpp`).

## Модель: свой игрок локально, мир на хосте

- На каждой машине `objPlayer` — **свой** игрок, он же `PlayerFind(0)`. Ввод, инвентарь, монеты, XP, снаряжение,
  интерфейс и меню остаются нетронутыми и уже раздельные.
- **Хост** — единственный источник правды о мире: ресурсы, мобы, дроп, постройки, сундуки, время, острова.
- **Гость** не симулирует мир: у него копии объектов хоста, которые двигает сеть. Свой спавн и ИИ у гостя выключены.
- Напарник на каждой машине — **марионетка**: экземпляр `objPlayer`, у которого перехвачены события
  (Step, Step_1/2, Mouse, Alarm и т.п. не выполняются; Draw — да, в контексте марионетки). Так как `objPlayer`
  наследует `parAlly`, враги выбирают его целью сами (`instance_nearest(x, y, parAlly)` в `parPathfind/Step_0`).

## Контекст актёра (`PlayerFind`)

`PlayerFind` всегда вызывается с n = 0 (проверено, ~350 раз за кадр). Хук возвращает **текущего актёра**:
по умолчанию локального игрока, но когда хост исполняет действие гостя — марионетку гостя. Тогда весь код игры,
который читает «игрока» (урон инструмента, навыки, баффы, снаряжение), берёт данные гостя — их зеркалим
на марионетку.

Выходы, адресованные игроку, при актёре = марионетка не применяются на хосте, а отправляются гостю:
`GainXp`, `GainItem`/`RemoveItem`, монеты, `DmgPlayer`, `EnergyDmg`, тосты и звуки.

## Действия гостя

| Действие | Как устроено в игре (проверено) | Что делает хост |
|---|---|---|
| Удар инструментом | `objPlayer_Step_0 → UseItem → ScriptCall → UsePickaxe`, внутри `with (цель) { killedByPlayer = room_speed; event_user(0) }` | Гость шлёт `hit(instanceId)`. Хост с актёром = марионетка вызывает `Perform_Event(цель, марионетка, ev_other, 10)` (`event_user(0)` = `FUN_016F2D00` → `FUN_017DA800(self, other, 7, 10+n)`) |
| Уничтожение объекта | В `Step` объекта при `hp <= 0` → `Destroy_0` → `GainXp`, `DropItem` (`parHerb_Destroy_0`) | Хост помнит, кто бил последним; при уничтожении ставит актёром этого игрока, и XP уходит ему |
| Подбор дропа | `parResource/Other_10` → `GainItem` к `PlayerFind(0)` | Хост решает, кто ближе; актёр = он |
| Урон гостю | Коллизия снаряда/моба с `objPlayer` → `DmgPlayer` по `PlayerFind(0)` | Считает гость по своим копиям врагов; на хосте коллизии с марионеткой гасим |
| Постройка, сундук, покупка острова | — (этап 4) | Запрос хосту, хост выполняет с актёром = марионетка |

## Меню и «пауза»

Глобальной паузы нет (проверено: при открытом меню `objPlayer` продолжает шагать). Около 30 объектов сами
проверяют `IsMenuOpen` (есть `parMenu`, `uiInventory`, `uiCrafting`, `uiBuild`, `luiManager`) и замирают.
В коопе хук `IsMenuOpen` возвращает реальное значение только для своего игрока и UI, для объектов мира — `false`.

## Culling

`WorldControl/Step_1` вызывает `CullObject` (деактивирует объекты вне `global.camera*`, кроме `antiCull`/`tempActive`)
и `ProcessCulls` (возвращает тех, кто снова в рамке). На хосте:
- `CullObject`: не вызывать оригинал, если объект в рамке вокруг гостя;
- `ProcessCulls`: после оригинала подставить в `global.camera*` рамку гостя, вызвать ещё раз и вернуть значения.

## Смерть

`objPlayer/Step_1` при `hp <= 0` вызывает `SaveGame` и создаёт `objGameOver`. В коопе перехватываем:
без сохранения и game over — телепорт на стартовый остров, полное здоровье.

## Зоны

`global.zoneCurrent` + `LoadZone` — одна зона на игру. Переход выполняет только хост; гостю уходит команда,
оба переносятся вместе. В v1 зоны кроме основного мира не поддерживаем.

## Несколько гостей (до трёх)

Звезда через хост ([MULTIPLAYER.md](MULTIPLAYER.md)): гости соединены только с хостом. У каждого сообщения есть
отправитель (`net::PeerId`: 0 — хост, у гостей — номер соединения, не переиспользуется). На каждого другого игрока —
своя марионетка; хост пересылает позиции гостей остальным и всё, что гость сообщает об общем мире (хранилища,
засыпка воды, квесты, музей, разблокировки, станки, сундуки-сокровища). Занятость сундуков и станков решает хост:
опоздавшему — отказ. Дроп, заработанный гостем, уходит только ему. Culling у хоста — по камере хоста и рамке
вокруг каждого гостя.

## Сеть

TCP поверх Hamachi, сокеты в DLL (WinSock), отдельный поток приёма, применение сообщений — в начале шага
`WorldControl` в игровом потоке. Объекты мира идентифицируются id экземпляра на хосте; у гостя — таблица
`hostId → локальный экземпляр`. Персонаж гостя хранится у хоста рядом с сейвом (`coop_guest_<имя>.json`).

## Открытые вопросы

- Как `objPlayer_Step_0` определяет цель удара (`GetSelectionData`) — нужно, чтобы гость указал её по id хоста.
- Постройки, сундуки, крафт на станциях, дроиды (`global.droids`) — разобрать по той же схеме.
- Какие переменные игрока читает код мира — их нужно зеркалить на марионетку.
