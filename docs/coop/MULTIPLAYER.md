# Кооп до 4 игроков — план

Сейчас кооп рассчитан на «хост + один гость» (SPEC.md: «больше 2 игроков — вне v1»). Цель — хост и до трёх
гостей. Делаем сразу на N игроков с лимитом 4: код для N не сложнее, чем для 4.

## Модель

- **Звезда через хост.** Гости соединены только с хостом. Всё, что касается других игроков, хост пересылает
  (ретранслирует) сам: гость не знает адресов других гостей.
- **Id игрока** (`net::PeerId`, u8): 0 — хост, у гостей — номер соединения на хосте (1, 2, 3, … растёт, не
  переиспользуется в пределах сессии хоста, чтобы опоздавшие сообщения ушедшего гостя не приписались новому).
- Всё спорное (станок, сундук, хранилище заняты) решает хост, а не договорённость двух сторон.

## Этапы

| # | Что | Можно играть |
|---|---|---|
| 1 | Сеть: много соединений, у сообщения есть отправитель, `SendTo`/`Send` (всем), вход и уход гостя не трогают остальных. Ответы конкретному гостю (персонаж, навыки, снимок мира) — только ему. Лимит гостей пока 1 | вдвоём, как раньше |
| 2 | Несколько марионеток (`puppet` по id игрока), `BeginActing(id)`, враги идут к ближайшему из всех, позиции гостей хост пересылает остальным гостям | втроём: видят друг друга |
| 3 | Атрибуция по id: удары, XP, дроп, крафт, постройки гостя; персонаж и навыки по соединению | втроём: основная игра |
| 4 | Ретрансляция и арбитраж на хосте: квесты, музей, разблокировки, станки, хранилища, сундуки-сокровища, засыпка воды | вчетвером без конфликтов |
| 5 | Culling по рамке каждого игрока вместо общего прямоугольника; сверка мира по каждому гостю со сдвигом во времени | FPS хоста при разбросанных игроках |
| 6 | Меню «x/4», тесты на 3–4 копиях игры, SPEC/STATUS | — |

После каждого этапа — `tools/gametest/regress.ps1` (вдвоём должно работать всё, что работало). Лимит гостей
поднимается до 3 после этапа 3; до этого `COOP_DEBUG_MAX_GUESTS=<n>` у хоста — для проверки сети.

## Этап 1 подробно

### `net`
- `Message.from` — отправитель (у гостя всегда 0 = хост; у хоста — id соединения). Формат кадра на проводе не
  меняется: отправителя знает принимающая сторона по сокету.
- Хост: список соединений (до `maxGuests`), у каждого свой поток приёма и свой мьютекс отправки — большой снимок
  мира одному гостю не держит отправку остальным. Лишнее соединение сверх лимита отклоняется, как сейчас второе.
- `Send(type, …)` — хост: всем гостям; гость: хосту. Поведение для двоих не меняется.
- `SendTo(peer, type, …)` — одному.
- `Peers()` — id подключённых сейчас; `IsConnected()` — есть ли хоть одно соединение.
- `ConnectHandler(PeerId)`.
- `StartHost(port, maxGuests)`.

### Ответы одному гостю
- `character::HostHandle`: персонаж — `SendTo(message.from)`; имя гостя — по id (`HostGuestName(peer)`),
  `kCharacterSave` сохраняется под именем отправителя.
- `skills`: `HostOnGuest(name, peer)` → `SendTo`; присланные навыки сохраняются под именем отправителя.
- `world`: снимок мира — тому, кто представился; очередь запросов, если гости входят одновременно.

### `session`
- Приветствие (`kHello`) — каждому новому соединению, а не при переходе «не было связи → есть».
- Уход гостя: забываем его (имя). Общий сброс (марионетка, реплики, замки) — когда ушли все, как сейчас.
- LAN-анонс: игроков = 1 + число гостей.

### Итог этапа 1 (2026-10-20)

Сделано всё перечисленное выше; кроме того, LAN-анонс несёт вместимость сессии (байт в конце пакета; сборка
без него читается как «2 игрока»), меню показывает «x/вместимость».

Проверено: `regress.ps1` (все PASS), `hostleave.ps1`, `rejoin.ps1` — вдвоём как раньше; после повторного создания
и повторного входа гость получает новый id (2), персонаж при «Save and exit» сохраняется под его именем.
Втроём (`COOP_DEBUG_MAX_GUESTS=2`, скрипт в духе coopflow): оба гостя подключились, каждому — свой ответ
о персонаже и свой снимок мира, второй гость вошёл в мир; первый гость закрыт — хост и второй гость остались на
связи. Игровая синхронизация втроём пока не работает (этапы 2–4): позиции гостей у хоста — одна марионетка.

Найдено для следующих этапов:
- Два гостя с одинаковым именем делят один файл персонажа у хоста (`coop_guests/<имя>.cin`) — на этапе 3
  отказывать второму или добавлять суффикс.
- Два гостя на одном ПК (тесты) делят временный слот 99 и `coop_guest_character.cin` — на этапе 6 нужен
  отдельный слот на процесс (например, `COOP_DEBUG_GUEST_SLOT`).

## Итог этапа 2 (2026-10-20)

- `puppet`: марионетка на каждого другого игрока (по id), `BeginActing(id)`; враги у хоста идут к ближайшему
  из всех игроков; спутники у гостя следуют за марионеткой хоста.
- Позиции: каждый шлёт свою хосту (гость) или всем (хост); хост пересылает позицию гостя остальным гостям
  (`kPeerState` = 8) и сообщает об уходе гостя (`kPeerGone` = 9). Состояние ушедшего гостя, оставшееся во
  входящих, не пересылается — иначе марионетка вернулась бы.
- Удары, постройки и засыпка воды выполняются на хосте как марионетка того гостя, кто их прислал; ответ на
  постройку — только ему. XP за уничтоженное — тому гостю, кто бил последним.
- Culling у хоста растягивает рамку на всех гостей (один общий прямоугольник — этап 5); сверка мира пока вокруг
  первого гостя.

Проверено: `regress.ps1`, `rejoin.ps1` — вдвоём как раньше. Втроём (`COOP_DEBUG_MAX_GUESTS=2`): у каждого две
марионетки других (на скриншотах хоста и второго гостя по три персонажа с инструментами); первый гость закрыт —
его марионетка исчезла у хоста и у второго гостя.

Ещё не втроём (этап 3): дроп гостей (`g_guestDrops`, `kOwnerGuest`) — общий на всех гостей; урон по
марионеткам; монеты, навыки и персонаж — по соединению уже, но не проверены втроём.
