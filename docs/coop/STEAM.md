# Steam-приглашения — можно ли и как

Задача из QUESTIONS.md (2026-10-19): вместо IP / LAN / Hamachi — «пригласить друга через Steam», как в коопе на
Modding API, который видел пользователь.

## Ответ: можно

Игра уже грузит и инициализирует `steam_api.dll` (Steamworks SDK ~1.41: `SteamClient017`, `SteamUser019`; сама
игра пользуется только достижениями, таблицами рекордов, мастерской и облаком). Наш `version.dll` может вызывать
её плоский API напрямую — всё нужное в экспорте есть: лобби (`ISteamMatchmaking`), P2P-сеть (`ISteamNetworking`:
`SendP2PPacket`/`ReadP2PPacket`/`AcceptP2PSessionWithUser`), окно приглашения (`ActivateGameOverlayInviteDialog`),
Rich Presence, регистрация колбэков (`SteamAPI_RegisterCallback`/`RegisterCallResult`).

Проверено пробником (`native/src/steam.cpp`, `COOP_DEBUG_STEAM=1`, 2026-10-20), в запущенной игре:
- интерфейсы `SteamFriends015` и `SteamMatchMaking009` получены, имя игрока читается;
- игра сама вызывает `SteamAPI_RunCallbacks` каждый кадр (300 из 300 шагов) — колбэки приходят в игровом потоке,
  отдельный цикл не нужен;
- лобби «только для друзей» на 4 места создаётся (~0,4 с, `k_EResultOK`), данные лобби записываются;
- оверлей Steam открывает «Выберите, кого пригласить» поверх Forager.

Не проверено (нужны два аккаунта Steam на двух ПК): приход приглашения другу, вход в лобби, P2P-соединение.

## Как будет работать

1. **Хост** нажимает CREATE (как сейчас). Дополнительно создаётся лобби Steam «только для друзей» на 4 места; в
   данных лобби — версия протокола и имя мира; Rich Presence `connect` = `+connect_lobby <id>` (тогда в списке
   друзей у хоста появляется «Присоединиться к игре»).
2. **Пригласить**: кнопка INVITE (на экране COOP и клавиша в мире) открывает окно приглашения Steam; также работает
   стандартное «Пригласить в игру» из списка друзей в оверлее.
3. **Гость** нажимает «Присоединиться» в приглашении:
   - игра запущена — приходит `GameLobbyJoinRequested_t` → `JoinLobby` → `LobbyEnter_t` → владелец лобби = хост;
   - игра не запущена — Steam запускает её с `+connect_lobby <id>` → после главного меню то же самое.
   Дальше — обычный вход гостя (персонаж, снимок мира…), только соединение идёт через Steam.
4. **Соединение** — Steam P2P (`ISteamNetworking`, надёжный канал, ретрансляция Steam): **без IP, проброса портов
   и Hamachi**. В `net` — второй транспорт рядом с TCP: соединение знает, чем оно сделано (сокет или SteamID);
   кадры те же (`[u32 size][body]`), режутся на куски ≤ 1 МБ (предел надёжного P2P-пакета) и склеиваются потоком.
   Хост принимает P2P-сессию только от участников своего лобби. LAN/IP остаются как есть: в одной сессии могут быть
   гости и по TCP, и через Steam.

Альтернатива попроще — Steam только как «доска объявлений» (в лобби лежит IP хоста, соединение по TCP) — почти ничего
не даёт: другу всё равно нужен доступный IP (Hamachi).

## Объём и риски

- Модуль `steam` (лобби, приглашения, колбэки, `+connect_lobby`) — ~250 строк; Steam-транспорт в `net` — ~250;
  кнопка INVITE и клавиша в мире — немного. Пробник уже даёт основу (вызовы API, объект колбэка как `CCallbackBase`).
- `ISteamNetworking` в новых SDK помечен устаревшим, но в этой `steam_api.dll` другого нет и он работает (сервера
  Steam его поддерживают); заменять DLL игры на новую не нужно.
- Лобби и P2P работают для любого appid (Forager 751780) без настроек в Steamworks.
- **Тестировать автоматически на одном ПК нельзя**: P2P с самим собой невозможен, нужен второй аккаунт Steam на
  втором ПК — финальная проверка за пользователем (с другом). Логи с обеих сторон покажут, где споткнулось.
- Оверлей Steam должен быть включён у игроков (по умолчанию включён).
