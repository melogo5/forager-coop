# CoopTest — кооператив для Forager

> **Заморожен.** Первый прототип на Mod API; дальше кооп делается нативным патчем —
> см. [native/README.md](../../native/README.md). Ниже — описание на момент заморозки.

Экспериментальный мод для игры вдвоём по сети (TCP) на официальном Modding API Forager
(игра 4.1.9, API 1.0.1). Сейчас это рабочий прототип: два игрока видят друг друга и делят один
мир, но многие системы игры ещё не синхронизируются.

## Установка и запуск

1. Папка мода должна лежать в `%LOCALAPPDATA%\Forager\mods\CoopTest` (у нас это junction на
   `mods/CoopTest` в репозитории — правки сразу видны игре).
2. В игре: **MODDING → включить CoopTest → COMPILE**. В консоли (клавиша **T**) должно быть
   `[CoopTest] loaded`.
3. **Клиент должен играть на копии сейва хоста** — острова и рельеф берутся из файла сохранения,
   по сети передаются только объекты на них. На одном ПК достаточно загрузить один и тот же слот.
4. Хост: `/cohost [порт]` (по умолчанию 7777). Клиент: `/cojoin <ip> [порт]`.

Вторая копия игры на одном ПК запускается благодаря `steam_appid.txt` (`751780`) в папке игры —
`Forager.exe` открывается напрямую, без Steam.

## Команды

| Команда | Что делает |
|---|---|
| `/cohost [порт]` | открыть сервер и ждать игрока |
| `/cojoin [ip] [порт]` | подключиться к хосту (по умолчанию `127.0.0.1:7777`) |
| `/coloop [порт]` | самопроверка сети в одной копии игры (подключение к самому себе) |
| `/costatus` | состояние сокетов и счётчики |
| `/costop` | закрыть сессию |
| `/comenu` | безопасно выйти в главное меню (для тестов) |

## Что работает

Проверено в игре (автотестом с двумя окнами и/или вручную):

- **Сеть**: подключение, пинг, keepalive (в том числе пока у игрока открыто меню — игра при
  этом на паузе), таймаут 5 с при пропаже второй стороны.
- **Второй игрок**: голубой «призрак» с подписью P2 на месте другого игрока.
- **Ресурсы** (деревья, камни, руды, кристаллы и т.п.) и **растения** (кусты, цветы, посевы):
  при подключении хост присылает снимок мира; новые ресурсы спавнит только хост, случайный спавн
  клиента подавляется; добытое одним игроком исчезает у другого. Добычу получает тот, кто добыл.
- **Враги**: спавн только у хоста, позиции и HP синхронизируются, урон обоих игроков
  складывается, дроп и опыт — у добившего.
- **Покупка острова**: клиента выбрасывает в меню с плашкой, после загрузки сейва он сам
  переподключается и видит тот же остров.
- **Выход из сессии**: уход любого игрока (`/costop`, выход в меню, «Save and exit», потеря связи)
  показывает плашку; если ушёл хост — клиент уходит в главное меню.

## Сделано, но ещё не проверено в игре

Последние исправления, написанные после сообщений о багах:

- **Покупка острова определяется по монетам на экране Buy land** — вместо чтения
  `global.ownedLands`, которое портило данные игры (см. «Важные особенности»).
- **Владение врагами**: каждым врагом управляет ближайший к нему игрок (с запасом 25%), второй
  игрок только подтягивает врага к его позиции. Должно убрать «откидывание» слаймов назад после
  прыжка на клиента и позволить врагам атаковать обоих игроков.

## Известные проблемы и ограничения

- **Игра по сети с другом** требует ручного копирования сейва хоста перед подключением и после
  каждой покупки острова (моды не умеют работать с файлами).
- Плашки пока на английском.
- В консоли остаются отладочные сообщения `[peer] …` — их хост шлёт клиенту для диагностики.
- В сейве тестового слота могли остаться испорченные данные островов от старой версии мода
  (ошибка `REAL argument is undefined` на экране Buy land). Если ошибка повторится на свежей версии
  мода — начать новый тестовый мир.

## Устройство

| Файл | Что внутри |
|---|---|
| `Main.gml` | сессия: команды, сокеты, протокол, призрак P2, плашки, выход в меню, острова |
| `World.gml` | ресурсы и растения: снимок мира, спавн, удаление, сетевые ID (`coNetId`) |
| `Mobs.gml` | враги: спавн, владение, поток позиций и HP, смерть |

Модель: **хост авторитетен** в том, что появляется в мире; уничтожение — у того, кто это сделал;
врагов симулирует ближайший игрок. Протокол — пакеты `u8 type` + данные поверх
`network_send_packet` (TCP), список типов — в шапках файлов.

### Важные особенности движка и API (выяснены на практике)

- **При выходе в главное меню игра полностью выгружает моды** и стирает их `global.*`. Что должно
  пережить выход, хранится в переменных самой игры (`variable_global_set("coopCarry…")`).
- **Сетевое событие во время выгрузки модов роняет игру** (ошибка `ref_map_wrap` в
  `WorldControl` или падение движка). Поэтому сессия закрывается *до* перехода в меню, а сам переход
  откладывается на 1,5 с; переходы игры (`objTransition`) не в игровые комнаты перехватываются.
- **Нельзя оборачивать структуры данных игры** (`variable_global_get(..., "grid")` и т.п.): при
  выгрузке модов загрузчик уничтожает их вместе с данными мода.
- **`OnStep` не вызывается на паузе** (любое открытое меню игрока); всё, что должно работать всегда,
  живёт в `OnDrawGUI` на своём счётчике кадров.
- `instance_activate_object` будит объекты только к следующему кадру — снимок мира двухфазный.
- В GML `-1` — это `self`: «пустые» ссылки на экземпляры — только `noone`.
- `instance_destroy()` без аргумента интерпретатор модов не принимает — нужно `instance_destroy(id)`.
- Ресурсы и враги вызывают `OnResourceSpawn`/`OnMobSpawn` ещё до окончательной настройки (тип руды)
  — отправка откладывается на кадр. Сбор растений события не даёт — отслеживается опросом.

## Будущие задачи

**Сначала**
- [ ] Проверить в игре владение врагами и новое определение покупки острова.
- [ ] Проверить добычу ресурсов и бой с обеих сторон.

**Мир**
- [ ] Постройки (`parStructure`): строительство и разрушение, печи/кузницы и т.п.
- [ ] Сундуки, хранилища (`objVault`), содержимое построек.
- [ ] Посадки игроков (семена, саженцы) и рост растений.
- [ ] Предметы на земле (дроп, который не подобран).
- [ ] День и ночь, погода.
- [ ] NPC, квесты, подземелья и другие комнаты (сейчас синхронизируется только `rmGame`).

**Игроки**
- [ ] Анимация, направление и инструмент призрака вместо статичного спрайта.
- [ ] Враги атакуют призрака у хоста (сейчас ИИ на стороне хоста видит только игрока хоста).
- [ ] Общие навыки, достижения, купленные острова — согласовать модель (общие или раздельные).

**Сеть и удобство**
- [ ] Программа-компаньон для передачи сейва хоста клиенту (мод может обращаться к ней через `http_get`).
- [ ] Подключение через интернет без проброса портов (relay-сервер или VPN-инструкция).
- [ ] Русский текст плашек, меню подключения вместо консольных команд.
- [ ] Убрать отладочные сообщения, переименовать мод из CoopTest в рабочее имя, опубликовать в Workshop.

## Тестирование

Автотесты на двух окнах игры — `tools/gametest/` (`gamectl.ps1` управляет окном через сообщения
Windows и делает скриншоты, `coopsession.ps1` поднимает сессию в тестовом слоте 1).
